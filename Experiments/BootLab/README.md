# 계산형 실험 — experiment/boots-formula

**상태: DLL·모의 API·실제 DLL 로딩 테스트 통과. 실제 월드 속도·저장·멀티플레이 미검증.**
현재 게임에는 설치하지 않았습니다. 이 브랜치의 실험은 이 폴더에 있습니다. 기존 SpeedMod/설치 EXE는 기준 버전 코드입니다.

## 방식과 범위

원본 신발 ItemId·등급·레벨·강화는 바꾸지 않습니다. EML과 새 아이템 정의가 필요 없습니다.
기존 랜덤 범위의 중간값을 반올림하여 적용합니다. 같은 레벨·등급이면 같은 보너스이며 랜덤 개체 차이는 없습니다.
예: 레벨 1 일반 +3%, 전설 +18%; 레벨 45 일반 +13%, 전설 +60%.
수치는 기존 설계 범위에서 계산한 실험값입니다.

DLL은 기본적으로 **읽기 전용 미리보기**입니다.
개발자 명령으로 켠 경우에만, 혼자 호스트한 테스트 캐릭터의 Movement_Sprint에 8 × 보너스%를 더합니다.
기존 질주 수치는 기준값에 포함하며, 반복 가산하지 않습니다. 맨발·disable·다른 플레이어 참가 시 알고 있는 추가분을 회수합니다.
세션·슬롯·아이템·컴포넌트 크기·Movement 루트/범위·원본 스프린트 8을 확인한 뒤 프로그램의 추적 가능한 쓰기를 사용합니다.
외부 효과가 속도 필드를 바꾸면 추측해서 덮어쓰지 않고 중단합니다. 이 경우 자동 회수를 보장할 수 없으므로 테스트 캐릭터를 재로드해야 합니다.
실제 게임 스키마에서 Movement는 do_not_save·server_only로 표시됩니다. 다만 실제 저장 후 재시작/로컬 이동 예측 검증은 아직입니다. 일반 플레이용으로 배포하지 마세요.
게임 업데이트에 독립적이라는 뜻도 아닙니다. 정확한 빌드 1283531을 검사합니다.

## 시험 순서

1. 기존 랜덤 버전의 변형 신발이 있는 캐릭터로 바로 교체하지 않습니다. 기존 복구·제거 절차를 먼저 완료하거나 별도 깨끗한 테스트 캐릭터/월드를 사용합니다.
2. EMF가 있는 별도 테스트 게임의 emf/mods/speedmod_formula/에 ZIP 안의 동일 이름 폴더를 넣습니다. EML이나 다른 로더는 바꾸지 않습니다.
3. 혼자 호스트한 월드에서 콘솔에 speedmod_formula.status를 입력해 보너스를 확인합니다.
4. 테스트 캐릭터에서만 speedmod_formula.apply test-character를 입력합니다.
5. 같은 구간 질주 시간을 미리보기/적용 상태에서 비교합니다. 기본 신발 툴팁에는 추가 표시하지 않습니다.
6. 저장·종료 전 speedmod_formula.disable를 입력하고 status에서 delta=0을 확인합니다. conflict=1이면 테스트 캐릭터를 재로드하고 원래 속도를 확인해야 합니다.
7. 테스트 게임에서 종료 후 이 실험의 폴더만 빼면 됩니다. 이 모드는 신발 ID를 변형하지 않습니다.

speedmod_boots가 함께 로드됐거나 SM02_ 변형 신발이면 적용을 거부합니다.
참가자·전용 서버는 지원하지 않습니다. 실시간 효과/전투/사망/재접속과 기본 UI 표시는 추가 검증 대상입니다.

## 빌드·검증

Visual Studio C++ Build Tools가 있는 Windows에서 build.cmd를 실행합니다.
build/speedmod_formula.dll과 build/mod.json이 생깁니다.
테스트는 기존 +6% 유지, 반복 중첩 방지, 해제/맨발/참가자 진입, 오래된 세션/아이템, 쓰기 거부, 외부 변경 충돌을 검사합니다.
abi_smoke는 컴파일한 DLL을 실제 LoadLibrary로 열어 버전 거부·명령 등록·읽기 전용 CSV 캡처를 확인합니다. 게임 월드 시험을 대신하지 않습니다.
package.ps1은 통과한 빌드로 공유용 ZIP과 SHA-256을 만듭니다.
