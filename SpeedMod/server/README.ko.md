# SpeedMod 0.3 — 서버 기록 방식

호스트 플레이용 개발 버전입니다. 빌드 1285601 / EMF 0.4.1에서 소스·데이터 검증을 했습니다.
현재 배포물은 새 신발 ItemId, 드롭 아이템 복제, 기본 아이템 툴팁 수정, 실행 파일 메모리 패치를 사용하지 않습니다.

신발의 실제 레벨·등급으로 추가 질주속도를 추첨합니다. 범위는 기존 설정과 같고 `config.ini`로 변경합니다.
게임의 기본 장비 효과 프로그램을 사용하는 임시 효과 100개(1~100%)만 정의합니다.
서버가 장착된 신발에 해당 효과 하나를 유지합니다. 맨발·교체·disable에서는 제거하며, 런타임이 멈추면 1초 수명이 만료됩니다.
원본 신발의 ItemId·레벨·등급·강화·염색·내구도는 변경하지 않습니다. 외형 신발은 제외합니다.

호스트 본인이 신발을 장착·교체하면 화면 상단에 `SpeedMod: Sprint bonus +17%`처럼 추가 보너스를 몇 초간 표시합니다.
같은 신발의 주기 검사나 임시 효과 갱신에서는 반복하지 않습니다. 벗었다가 다시 장착하면 다시 표시합니다.
알림은 서버 기록이 저장되고 해당 임시 효과가 확인된 뒤 표시합니다. 기본 툴팁은 그대로이며 참가자의 장착은 호스트에게 알리지 않습니다.

## 기록과 연결 실패

기록은 **호스트 PC**의 `emf/mods/speedmod_server/records/world-XXXX.txt`에 저장됩니다.
XXXX는 월드 저장소·슬롯 번호입니다. 파일 교체 전에 디스크로 flush하며 이전 파일은 `.bak`에 남깁니다.
새 추첨값은 저장 성공 뒤에만 적용합니다. 손상·쓰기 오류가 있으면 보너스를 멈추고 원본 게임 수치는 유지합니다.

- 실행 중: PIDE를 현재 세션의 임시 추적에만 사용합니다. 파일에는 저장하지 않습니다.
- 재시작: 계정 또는 보관함 좌표 → 인벤토리 페이지 → 칸 + 내부 아이템 이름·레벨·등급으로 연결합니다.
- 연결이 없거나 여러 후보가 겹치면 한 번 새로 추첨하고 즉시 기록합니다. 다음 검사마다 다시 뽑지 않습니다.
- 새로 가져온 신발도 별도 등록 없이 대상입니다. 같은 서버의 추적이 유지되는 이동·거래·강화에서는 기존 값을 유지합니다.
- 이름이 같은 두 물건을 관측 사이에 바꾸거나 서버 밖에서 수정하면 완전한 개체 구별을 보장할 수 없습니다.
  같은 이름·레벨·등급이 같은 칸에 남으면 기존 값을 물려받을 수도 있습니다. 이 방식은 영구 아이템 식별자가 아닙니다.
- 연결 실패나 다른 서버 왕복을 이용한 재추첨은 막지 않습니다. 서버 기록 파일은 다른 서버로 자동 전송되지 않습니다.
- 같은 계정의 여러 캐릭터를 별도로 식별하지 못합니다. 같은 월드 슬롯을 지우고 새 월드를 만들면 해당 슬롯 기록도 따로 보관/초기화해야 합니다.
- 월드 세이브와 장부 파일은 서로 다른 저장입니다. 원자적 파일 저장은 보장하지만 두 파일의 동시 커밋은 보장하지 않습니다.

## 구형 변형 신발 삭제

이번 전환에서는 사용자가 구형 신발 삭제를 허용했습니다.
0.2.x 배포 manifest에서 검증한 11,716개 ID는 **삭제 대상 확인에만** 씁니다. 새 보너스 판별과 저장에는 사용하지 않습니다.
게임에 로드된 모든 인벤토리를 검사하므로 캐릭터·창고가 대상입니다. 아직 로드되지 않은 창고는 나중에 로드될 때 검사합니다.
같은 숫자의 ID가 현재 게임의 정상 아이템으로 등록돼 있으면 삭제하지 않습니다.
삭제 직전에 세션·칸·아이템·PIDE·수량을 다시 확인하며, 게임의 추적 가능한 Inventory 쓰기로 칸을 비웁니다.
장착된 구형 신발은 장비 갱신 이벤트를 보냅니다. 떨어진 PIDE는 다음 서버 tick에서 검증 후 정리합니다.
데이터 정의가 사라져 게임이 먼저 구형 신발을 제거한 경우 모드의 삭제 카운트에는 포함되지 않을 수 있습니다.

## 설치와 명령

[설치 ZIP 다운로드](https://github.com/keyboardBK/EnshroudedMods/raw/refs/heads/feature/random-boot-sprint/SpeedMod/server/distribution/SpeedMod-Server-0.3.0.zip) → 압축 해제 → 게임 종료 → `install.cmd` 실행. Steam 라이브러리에서 게임 폴더를 자동으로 찾습니다. 자동 감지가 안 되거나 여러 설치본이 있으면 `install.cmd -Game "게임 폴더"`로 지정합니다.

설치하면 구형 SM02 변형 신발이 로드될 때 삭제됩니다. 게임 원본 신발과 새 버전 보너스를 받은 신발은 삭제하지 않습니다. 기존 구성과 세이브는 `SpeedModInstaller/backups/*-server03/`에 보관합니다.
EMF 0.4.1의 내장 EML 빌더가 별도 복사본에서 효과를 만들며, 원본 `.kfc`는 수정하지 않습니다.
기존 SpeedMod 부트스트랩과 EML 체인은 제거합니다. 다른 체인 항목은 유지합니다.
참가자도 같은 효과 데이터를 읽을 수 있도록 같은 패키지를 설치해야 합니다. 서버 기록은 호스트만 관리합니다.
새 게임 빌드에서 모딩 API/구조가 달라지면 DLL은 로드를 거부하며 게임 자체를 종료하지 않습니다.

EMF 콘솔(ESC 아래 키):

- `speedmod.status`: 신발별 보너스·기록 수·구형 신발 삭제 수
- `speedmod.disable`: 보너스 중단(임시 효과는 최대 1초 후 만료)
- `speedmod.enable`: 보너스 다시 적용
- `speedmod.reload`: 기록 파일을 다시 읽기

자동 테스트는 이동·거래·동일 이름·재시작 개체 번호 변경·모호한 연결의 단발 추첨·원자 저장·세션 격리·삭제 직전 검증·효과 중복 방지·실제 DLL 로딩을 확인합니다.
장착 알림은 호스트 제한·반복 억제·재장착·같은 보너스의 신발 교체·재추첨·효과 대기·0% 보너스를 모의 API로 검증했습니다. 실제 화면의 알림 표시는 아직 별도 확인 전입니다.
EML CLI와 EMF 0.4.1의 공식 콘텐츠 DLL에서 효과 100개를 직렬화·패치하는 검사도 통과했습니다.
2026-11-04 실제 설치 후 시작 메뉴까지 진입하고 새 DLL·효과 복사본 로딩을 확인했습니다. 검사 게임은 정상 종료했으며 월드나 캐릭터는 열지 않았습니다.
실제 월드의 체감 속도·재접속·친구의 이동 예측은 아직 별도 플레이 검증이 필요합니다.
