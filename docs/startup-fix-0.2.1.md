# 0.2.1 랜덤 버전: 시작 오류 수정과 검증

작업 브랜치: `feature/random-boot-sprint`. 실제 월드의 효과·아이템 복구·저장·멀티플레이 검증은 남아 있는 개발 버전입니다.

## 원인

0.2.0은 게임 데이터를 역직렬화하는 검사는 통과했지만, 실제 메뉴까지 진행됐는지 확인하지 못했습니다. GPU 프레임이 처음 나왔다는 로그를 메뉴 검증으로 잘못 판단했습니다.

- 게임 클라이언트 빌드 1283531은 GF_Resource 메모리 영역을 490 MiB로 고정합니다. 전체 신발 변형을 추가하면 영역 끝을 넘는 복사에서 충돌했습니다. 최초 덤프의 실제 충돌 위치는 memcpy 경로의 RVA `0x13cb37b`였습니다.
- 오류 보고용 보조 프로세스가 같은 EML을 초기화하면서 이미 게임에서 열어둔 KFC 파일에 쓰기를 시도해 `os error 32` 및 `Failed to create AppState`가 후속 표시됐습니다.
- 메모리 문제를 해소한 뒤에는 복제한 아이콘 때문에 기본 8,192개 UI 테이블이 넘쳤고, `out of game ui textures` 경로(RVA `0xa561f7`)에서 중단됐습니다.

## 최종 수정

- `speedmod_bootstrap.dll`을 EML보다 먼저 EMF 체인에서 실행합니다. 디스크 실행 파일의 SHA-256과 정확한 메모리 초기화 명령어를 검증한 뒤 GF_Resource 초기값을 768 MiB로 바꿉니다. 변경 대상은 실행 중 프로세스 메모리의 4바이트이며 실행 파일은 수정하지 않습니다.
- 일반 EMF 모드는 메모리 초기화 뒤 비동기로 로드돼 이 보정을 하기에는 늦으므로, 별도 부트스트랩이 필요합니다. 런타임 DLL은 부트스트랩 적용 여부도 검사합니다.
- 새 신발의 저장 ID와 리소스 GUID는 유지하고, UI 조회용 `ItemInfo.objectId`는 원본 신발 GUID로 공유합니다. 새 아이콘 리소스를 생성하지 않습니다. UI/GPU 테이블 용량을 늘리는 실험은 제거했습니다.
- EML에서 모든 ItemInfo의 본문을 읽으면 변경하지 않은 항목까지 다시 쓰기 대상으로 잡힙니다. 충돌 검사에는 GUID 메타데이터를 쓰고 신발 후보만 본문을 읽어 불필요한 재작성을 줄였습니다.
- 116종 × 101개 변형, 기존 랜덤 범위와 저장 ID 규칙은 유지합니다.

## 확인한 결과

- MSVC `/W4 /WX` 빌드와 런타임 모의 테스트 통과. 초기화 명령어의 원본·확장 상태, 다른 명령어 거부 검사 포함.
- 실제 패치 파일 재추출: ItemInfo 15,984개 중 기존 4,268개는 원본과 동일. 변형 11,716개의 등록 ID·질주 설정·툴팁 합산, 기존 다른 옵션 보존 검사 통과.
- UiTextureResource는 5,706개로 유지. 11,716개 변형이 모두 원본 아이콘을 참조하고 별도 변형 아이콘 리소스가 없음을 확인.
- 전체 랜덤 데이터로 실제 메뉴 화면 확인 후 정상 종료, 0.2.1 최종 빌드로 재실행해 메뉴 화면 재확인. 두 번째 실행에서 모드 버전 0.2.1 로드와 2,162프레임 진행, 신규 충돌 없음 확인.
- 실행 파일 SHA-256은 원본 `0403981fd2e8ad18bd8c5698dff03c8d505b5a46677832c496db9c645513f2a6`와 동일.
- 월드는 열지 않았습니다. 실제 신발 툴팁·질주 효과, 창고·거래, 저장·재시작, 멀티플레이는 별도 검증 대상입니다.

## 제약

호스트와 참가자 모두 같은 EML 데이터·런타임·부트스트랩이 필요합니다. 정확한 클라이언트 실행 파일만 지원하며 전용 서버 실행 파일은 현재 지원하지 않습니다. 아이템 복구 전 데이터 제거 금지 조건은 README를 따릅니다.
