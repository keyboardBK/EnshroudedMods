# SpeedMod 요구사항과 검증 항목

## 0.3에서 확정한 변경

- 사용 환경: 게임 클라이언트에서 방을 여는 호스트. 실제 신발 레벨·등급으로 서버가 추첨합니다.
- 원본 ItemId를 유지합니다. 드롭 아이템을 복제하거나 종류별 변형 아이템을 등록하지 않습니다.
- 서버가 내부 이름과 마지막 보관 위치로 기록합니다. 실행 중 개체 번호는 세션 내 추적에만 사용합니다.
- 연결 성공 시 값 유지, 실패·모호함·처음 보는 신발은 한 번 추첨 후 저장합니다. 다른 서버에서 가져온 원본 신발도 대상입니다.
- 이 정책은 완전한 개체 식별이나 서버 간 값 고정, 재추첨 악용 방지를 보장하지 않습니다.
- 기본 툴팁 표시는 요구하지 않습니다. 임시 게임 효과로 장착 시 가산하고 해제 시 회수합니다.
- 0.2.x에서 전환하면 구형 변형 신발을 삭제합니다. 캐릭터와 로드된 창고를 대상으로 정리하며 미로드 창고도 이후 로드 시 처리합니다.
- 원본 게임 데이터는 수정하지 않습니다. EMF 0.4.1이 효과 정의 100개를 별도 복사본에 적용합니다. 구형 부트스트랩은 제거합니다.
- 현재 검증: 자동 테스트·실제 콘텐츠 빌드·설치 롤백·실제 게임 시작 메뉴/DLL 로딩. 실제 월드 효과·저장·멀티플레이 검증은 아직입니다.

구현과 제약: [서버 기록 안내](../SpeedMod/server/README.ko.md).

## 이전 0.2 요구사항 (참고)

0.2는 실제 신발 레벨·등급 기반 정수 보너스를 한 번 추첨하며, 같은 신발의 값은 강화·거래·창고·재접속 때 고정합니다.
기존 질주 옵션에 더하고 게임 기본 툴팁에 합산 표시합니다. 외형 신발은 제외합니다.

사용자 예시를 적용한 일반·전설의 양끝 범위와 개발 기본 중간 등급은 저장소 README 및 runtime/config.ini에 있습니다.
중간 레벨은 선형 보간 후 반올림하며, 설정 변경은 아직 추첨되지 않은 신발에만 영향을 줍니다.
추첨 당시 레벨과 등급을 사용하고 강화 후 재추첨하지 않습니다.

새 ItemId가 보너스를 저장합니다. 실행 중 개체 ID나 임시 세션 맵을 저장 키로 사용하지 않습니다.
다른 서버 이동은 이번 필수 범위 밖이며, 호스트와 참가자 모두 동일한 EML 데이터가 필요합니다.

## 실제 게임에서 남은 확인

1. 기존 신발·새 드롭 신발 모두 툴팁에 보너스가 나오고 실제 질주속도와 일치하는지 확인.
2. 기본 +6% 신발에서 추첨 보너스가 합산되고, 벗으면 장비 효과가 해제되는지 확인.
3. 같은 종류·레벨·등급인 서로 다른 신발의 표시와 보너스가 섞이지 않는지 확인.
4. A→창고→B, A→B 거래 및 재장착 후 수치 고정 확인.
5. 재접속·게임/서버 재시작 뒤에도 수치와 레벨·등급·강화·염색·내구도 유지 확인.
6. 강화 후 재추첨하지 않고 원래 방어·Perk 강화가 정상인지 확인.
7. 호스트·참가자 양쪽 속도와 서버 보정 확인.
8. restore 모드에서 원래 신발로 복구 후 저장·재시작 확인. 미로드/오프라인 아이템을 남긴 채 데이터 제거 금지.

현재 자동 테스트는 위 동작을 검증하는 모의 API 테스트입니다. 실제 저장·네트워크 결과를 대신하지 않습니다.
