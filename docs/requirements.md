# SpeedMod 다음 버전 요구사항

## 확정된 요구사항

- 개별 신발의 실제 아이템 레벨과 등급으로 추가 질주속도의 랜덤 범위를 정합니다.
- 기존 질주속도 보너스를 보존하고 추가 보너스를 더합니다.
- 같은 신발은 같은 서버/월드에서 거래, 창고 보관, 재장착 후에도 같은 값을 유지해야 합니다.
- 서버 재접속·재시작 후 유지도 검증 대상입니다. 실행 중 개체 ID만 저장 키로 삼아서는 안 됩니다.
- 신발 툴팁에 실제 저장된 보너스가 표시되어야 합니다. 표시와 실제 효과가 같은 값을 사용해야 합니다.
- 같은 종류·레벨·등급이라도 서로 다른 신발은 각자 추첨 결과를 가질 수 있어야 합니다.
- 다른 서버로 이동했을 때의 유지까지는 이번 필수 범위에 포함하지 않습니다.

## 사용자 예시

| 신발 레벨 | 일반 | 전설 |
|---|---:|---:|
| 1 | 추가 +1~5% | 추가 +15~20% |
| 45 | 추가 +10~15% | 추가 +20~100% |

중간 레벨 보간 규칙, 고급·희귀·영웅 범위, 정수/소수 단위, 강화 시 재계산 여부는 아직 확정되지 않았습니다.
이 예시는 현재 알파 설정을 바꾸지 않습니다. 현재 알파의 전설 보너스는 +30%입니다.

## 구현 조건

현재 알파는 착용자에게 임시 효과를 주는 구조여서 툴팁에 표시되지 않습니다.
다음 버전에서는 개별 아이템 저장과 툴팁 경로를 함께 구현해야 합니다.
재장착이나 매 프레임마다 다시 추첨해 수치가 바뀌어서는 안 됩니다.
게임의 기존 저장 필드를 근거 없이 덮어쓰거나, 서로 다른 신발의 표시가 섞이는 전역 툴팁 변경은 허용하지 않습니다.
새 리소스나 아이템 ID를 사용하는 방식을 택한다면 저장·거래·아이콘·강화·기존 아이템 복구 및 참가자 호환을 먼저 검증해야 합니다.

## 통과해야 할 게임 내 테스트

1. 같은 신발의 실제 보너스와 툴팁 수치가 일치합니다.
2. 벗기/재장착, A→B→A 교환 후 원래 값이 유지됩니다.
3. 플레이어 A→창고→플레이어 B, A→B 거래에서 값이 유지됩니다.
4. 재접속과 서버 재시작 뒤에도 값이 유지됩니다.
5. 같은 아이템 정의의 서로 다른 신발을 비교할 때 표시가 섞이지 않습니다.
6. 기존 질주 옵션·Runner 스킬과 합산하고, 해제하면 모드 보너스만 회수합니다.
7. 호스트와 참가자의 이동 속도 및 서버 보정이 정상입니다.
